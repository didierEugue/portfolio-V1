Ma différence

Ma différence et pas un autre ?

01

Satisfaction client, pas livraison

Je ne ferme pas un ticket quand ça compile. Je le ferme quand le client confirme que c'est ce qu'il attendait — même si ça demande un tour de plus.

02

L'IA m'accélère — je reste aux commandes

J'utilise Claude Code et Cursor au quotidien, mais c'est moi qui analyse, conçois et valide. L'IA exécute ce que j'ai déjà pensé — pas l'inverse.

03

J'analyse avant d'écrire la première ligne

Comprendre le métier, les contraintes, les cas limites — avant d'ouvrir l'IDE. Moins de refactoring, moins de surprises en production.

04

Je clarifie avant de me lancer

Si la demande est floue ou incomplète, je le dis et je pose les bonnes questions. Un malentendu détecté à J+0 coûte infiniment moins cher qu'un refactor à J+30.

05

Perfectionniste — sur le fond et la forme

Code propre, nommage cohérent, structure lisible. Pas juste pour livrer — pour que le prochain dev (ou moi dans 6 mois) comprenne sans avoir à déchiffrer.

06

Montée en contexte rapide

ERP, e-commerce, SaaS, migration legacy — background varié. Je m'adapte à l'existant, je comprends vite ce dont le projet a vraiment besoin, et je suis patient face à la complexité.

Études de cas

Quatre défis, quatre solutions

Ce que les projets ne montrent pas : le raisonnement derrière les choix techniques.

01

Backoffice Supreme — SaaS de création de sites vitrines

Symfony 7 · Next.js · Multi-tenant · shadcn/ui
Le défi

Permettre à des professionnels sans compétences techniques de créer et gérer leur site vitrine via un backoffice moderne — sans exposer la structure interne, sans qu'un client puisse accéder à l'espace d'un autre, et sans nouvelle table en base à chaque nouveau type de section.

Approche technique
  • Isolation multi-tenant par TenantVoter Symfony — vérification automatique à chaque requête
  • Token JWT enrichi avec profil + espace client dès la connexion (zéro appel supplémentaire)
  • Sections en données flexibles (JSON) — 14 types de blocs ajoutables sans modifier le schéma BDD
  • Réorganisation par glisser-déposer (dnd-kit) + 3 à 6 variantes visuelles par section
14 types de sections
3 niveaux de permission
½ journée pour créer un site complet, sans coder
02

Bourbon Palto — Migration e-commerce sans perte

PrestaShop → React · Node.js · MongoDB
Le défi

8 ans d'historique PrestaShop à migrer vers une nouvelle plateforme sans interrompre la boutique, sans perdre un seul client ni une seule commande. Les structures de données source et cible sont incompatibles — chaque table exige une transformation.

Approche technique
  • Scripts Node.js dédiés par table (24 tables PrestaShop/Kerawen transformées)
  • Index optimisés, schéma MongoDB dénormalisé et accès directs sans ORM — gain de −60% sur les temps de requête
  • Cache localStorage deux niveaux côté React (filtres 30 min / produits 10 min)
  • Normalisation des variantes couleurs vers codes hex + dédoublonnage produits
−60% temps de requête
1M+ enregistrements migrés
8 538 clients préservés
03

Octogone ERP — Caisse certifiée & multi-sites

Node.js · React · MongoDB · PWA
Le défi

Un réseau de magasins multi-sites a besoin d'une caisse conforme à la réglementation anti-fraude TVA française : chaque transaction signée numériquement, archives inaltérables — le tout accessible sur mobile sans installation, y compris sans connexion internet.

Approche technique
  • Chaîne cryptographique HMAC-SHA256 sur chaque ticket — intégrité garantie pour contrôle fiscal
  • Accès MongoDB sans ORM via utilitaire maison (performances sur agrégations à fort volume)
  • Calculs monétaires en Decimal128 pour éviter les erreurs d'arrondi en caisse
  • PWA Workbox + IndexedDB — installable sur mobile et desktop, mode hors-ligne partiel
42 modules API
3 clients actifs (dont Bourbon Palto & Lina Market)
PWA offline mobile + desktop
04

Sekologia — LMS multi-tenant pour écoles malgaches

React 19 · Symfony 7 · TypeScript strict · Multi-tenant
Le défi

Projet personnel : concevoir un LMS multi-tenant full-stack pour écoles malgaches — 8 profils utilisateurs distincts (élève, enseignant, parent, finance…), backend Symfony 7.3 avec base de données isolée par établissement, et frontend développable indépendamment du backend.

Approche technique
  • Multi-tenant par base de données isolée (Symfony 7.3) — provisioning automatique d'une MariaDB dédiée par établissement, 12 migrations versionnées (V001–V012)
  • Mock Service Worker (MSW) — frontend développable sans backend réel : API simulée avec 8 comptes de test couvrant tous les rôles
  • TypeScript strict + Orval — clients API TypeScript auto-générés depuis la spec OpenAPI Symfony, zéro any, zéro drift
  • Session JWT en localStorage + 2FA email super admin — déconnexion automatique sur expiration ou réponse 401
8 profils utilisateurs
255 routes API (Symfony)
12 migrations tenant versionnées
